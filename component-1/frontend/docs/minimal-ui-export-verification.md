# Minimal interface and exports — 2026-10-19

The heading is now “Requirement Engineering”. The introductory instructions,
research/human-review badges and planned capabilities section were removed.
Backend health status, source review, project navigation, transcription,
extraction, classification and human label review remain available.

Full-discussion unclear-wording hints now follow the requirement review table.
They remain available when there is no extraction. Candidate-specific hints stay
inside row Details. These are English rule hints, not recovered requirements or
proof of clarity/completeness.

## Download contract

JSON preview and downloaded JSON have exactly four fields:

```json
{
  "project_title": "Simple Calculator",
  "project_description": "A basic calculator",
  "functional_requirements": ["Users shall be able to add two numbers."],
  "non_functional_requirements": ["Results shall appear within one second."]
}
```

Text contains the same information with numbered FR and NFR sections. Original
requirement wording and order within each group are preserved. Empty JSON groups
are empty arrays; text displays “None.”. Filenames still use the project title.
A saved human-reviewed label determines the group when available; otherwise the
model prediction determines it. Unreviewed predictions are flagged on the export
page, but no extra metadata is included in the downloaded document.

Record matching, stale-review rejection, loading/error guards and unsaved-edit
blocking remain in place. Detailed evidence, original predictions, reviews,
transcription provenance and model/run information remain in the application and
backend. This changes downloaded presentation only; no backend/API/model changes
or client record writes are involved. Previous reports describing rich downloads
are historical snapshots.
