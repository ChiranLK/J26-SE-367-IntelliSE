# Best-practice RAG for code generation

## Scope and research claim

This module retrieves reviewed best-practice rule cards for a generation task.
It is **RAG B** (code-quality / architecture guidance), not the future **RAG A**
over Component 4 defect explanations. Component 4 input remains simulated until
the real integration contract and evidence source are approved.

Two backends implement the same `BestPracticeStore` interface:

- `filter` (default): deterministic metadata, keyword, and priority ranking;
- `chroma`: metadata filtering followed by sentence-transformer embeddings,
  cosine similarity, priority tie-breaking, and stable rule-ID tie-breaking.

The Chroma collection name contains the embedding model name so vectors from
different models are not mixed. Startup synchronizes tracked rule cards by
adding/updating current cards and deleting stale IDs. `rag_db/` is a local,
rebuildable index and is excluded from Git.

## Configuration

```text
RAG_ENABLED=true
RAG_BACKEND=filter
RAG_PERSIST_DIR=rag_db
RAG_EMBEDDING_MODEL=all-MiniLM-L6-v2
```

`filter` requires no model download. `chroma` requires the separately declared
dependencies in `requirements-rag.txt`. No cloud LLM fallback is added. The
embedding model may be downloaded from its model repository on first use, then
runs locally.

## Generation evidence

Every new generation manifest records the enabled state, backend, embedding
model, canonical rule-corpus digest, module query, ordered rule IDs, and whether
the rules were actually included in an LLM prompt. This evidence is included in
the run evidence digest. It proves internal consistency, not authenticity or
scientific effectiveness.

Deterministic template modules may retrieve rules for audit visibility but are
explicitly marked `applied_to_prompt=false`. Currently only the legacy Task
service is generated by the local LLM, so it is the only module for which RAG
changes the prompt. Dynamic CRUD local-LLM generation remains unimplemented.

## Real semantic demo

```powershell
cd component-3
.\.venv\Scripts\python.exe -m pip install -r requirements-rag.txt
$env:RAG_BACKEND = "chroma"
.\.venv\Scripts\python.exe scripts\rag_demo.py
```

The printed rankings are observations from the configured real embedding model.
Offline unit tests use a fake deterministic embedding and are not semantic-
quality evidence.

## Ablation

`scripts/rag_ablation.py` runs the same ten controlled Task-MVP prompt variants
under `RAG_OFF`, `FILTER`, and `CHROMA`. It uses real local Ollama generation,
then counts `FAIL` findings from C3's deterministic structural verifier. It
makes 30 model calls, writes only below ignored `runtime/rag-ablation/`, never
executes generated JavaScript, and reports failed observations with a null
violation count rather than inventing a value.

The tasks are an implementer-authored controlled set, not an independent
benchmark. Structural conformance does not prove runtime correctness, semantic
preservation, C4 approval, or deployment readiness. With only ten rule cards,
filter and Chroma results may be similar; actual results must be reported even
when no improvement is observed.
